# Neon Relay

A Unity 6 sci-fi rooftop runner based on Hayden Livermore's Project B concept. Auto-run across an orbital city, jump rooftop gaps and power junctions, slide under laser gates, and hold magnetic wall panels to cross long gaps.

## Play

Open `Builds/NeonRelay/NeonRelay.exe` for the Windows game. Keep the executable beside its data folder and DLLs. A portable ZIP contains the same complete folder.

For editing, open **this root folder** in Unity **6000.3.10f1**, then open `Assets/NeonRelay/Scenes/NeonRelay.unity` and press Play. The pre-existing nested `RoofRunner` folder is not the game project. If the scene is missing, choose **Neon Relay > Create or refresh game scene** from Unity's menu. That command replaces the active scene, so save any editor work first.

## Controls and rules

| Control | Action |
| --- | --- |
| Space | Jump; also jump off an amber wall panel |
| S or Down arrow | Tap to slide for 0.78 seconds while grounded |
| Hold W or Up arrow | Attach to amber wall panels while airborne; 1.15 seconds of magnetic support |
| Escape | Pause/resume; return from submenus |
| Mouse | Menu buttons, volume sliders, callsign entry |

Forward movement is automatic. Land to refill wall charge. Touching a red hazard or falling below the rooftops ends the run. The score is **10 points per meter plus 100 per data cell**. Save a callsign on the results screen before leaving to record your score. The leaderboard stores the top ten scores locally, with difficulty shown beside each score.

Cadet runs at 8 m/s with more recovery sections, Courier at 10 m/s, and Phantom at 12 m/s. Each run begins with a safe roof, then jumping, sliding, gap, and wall-run modules before randomized modules. All roofs have compatible heights, bounded gaps, and generous approach/landing space. The same three movement mechanics work in every difficulty.

Scores and volume settings persist through Unity PlayerPrefs. Mid-run save/load, a shop, inventory, and health are not claimed features. Runs end on impact as in the production plan.

## Source map

- `Assets/NeonRelay/Scripts/RelayGame.cs`: state machine, fixed-substep kinematic movement, collision, scoring and persistence.
- `RelayWorld.cs`: generated rooftop modules, parallax skyline, courier artwork, particles and collectibles. Course collision uses explicit 2D bounds rather than physics rigidbodies.
- `RelayUI.cs`: runtime-built Unity uGUI Canvas, seven screens, sliders, buttons, and name input.
- `RelayAudio.cs`: original synthesized soundtrack and sound effects.
- `RelaySmoke.cs`: opt-in standalone integration tests, disabled in ordinary play.
- `Assets/NeonRelay/Editor/RelayBuild.cs`: scene creation and Windows build command.

The visual assets and course modules are generated by C# rather than external art packs or hand-authored prefabs. The scene is intentionally small; its game object creates the runtime world and UI on Play.

## Build and verify

Use **Neon Relay > Build Windows player** in Unity, or run Unity in batch mode with `-executeMethod NeonRelay.Editor.RelayBuild.Windows`. Close any editor using that same project before a batch build, or use an isolated copy.

Launch the built player with `-neonSmoke -logFile <absolute-log-path>` to run the integration suite. It tests three 90-second simulated runs, all three moves, collection, bounded course cleanup, pause, menu navigation, falling and impact failures, named-score persistence, and duplicate-score prevention. It writes screenshots and `QA/result.txt` beside the player. Test score storage is restored after a successful test. This test mode exits automatically.
